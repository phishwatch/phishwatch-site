PhishWatch

Privacy Policy

Last updated: September 28, 2026

Short version: PhishWatch analyses pages in your browser first. When local checks find risk, it sends the address of the flagged link or page and the names of the signals that fired. It never sends page content, credentials or clipboard contents. Our servers keep only the domain of a checked address, stored in Frankfurt, Germany (EU) and deleted after 30 days. Extra telemetry events are off by default and need your opt-in; those are deleted after 90 days.

1. Who we are

PhishWatch is operated by Deborshi Seal, Berlin, Germany. For privacy questions, contact privacy@phishwatch.io. PhishWatch is registered as a sole trader operating under German law.

2. What PhishWatch does

PhishWatch is a Chrome browser extension that detects browser-native phishing attacks at the moment of user interaction, intercepting at the click, redirect, and fake login stages, before credentials are exposed. All detection runs locally in your browser first. Cloud-based analysis is only triggered when local signals indicate risk.

3. Data we transmit during cloud analysis

When local analysis detects risk indicators, the following data is sent to our backend (api.phishwatch.io) for risk assessment:

Data elementWhat it is
Address being checkedFor a link you clicked: the full link address, used only to score it. For a page check: the page's origin and path plus the names of its query parameters, with their values removed. Example: https://suspicious-login.com/verify?session=. Our servers store only the domain (https://suspicious-login.com), never the path or query.
Signal IDsIdentifiers of phishing signals that fired locally, e.g. cross_origin_credential_post. No signal content, no page text.
Signal metadataBoolean flags and severity levels, e.g. has_password_field: true, risk_band: "high". All fields sanitised via allowlist before transmission.
Extension versionVersion string of your installed PhishWatch extension, e.g. 3.0
Session IDA randomly generated UUID created fresh for each browser tab session, held in memory only. Not persisted to disk. Not linked to your identity.
TimestampWhen the event occurred (ISO 8601 format).
Allowlist-based sanitisation: Transmission is controlled by sanitizeClientSignals() in the extension's background script. Any field not explicitly on the allowlist is stripped before transmission. Unknown fields fail closed and are never sent.

5. Scan records and opt-in telemetry

Scan records. Each backend check keeps a short record so we can operate and tune detection: the domain (scheme and host only), the risk result, the names of the signals that fired and a timestamp. These records contain no path, query, page content or user identifier, and they are deleted automatically after 30 days. The legal basis is legitimate interest in providing and improving phishing protection (GDPR Art. 6(1)(f)).

Telemetry. PhishWatch also includes an optional telemetry system that reports anonymised detection events from the extension. It is disabled by default. You must opt in via the extension popup, or your organisation enables it through managed browser policy, before any of these events are sent.

When telemetry opt-in is enabled, the following event types may be recorded:

Event typeWhen it fires
scanEach time a URL is assessed by PhishWatch
warningWhen an overlay warning is shown to you
decisionWhen you act on a warning (proceed, cancel, or report false positive)
session_incidentWhen a redirect chain and a cross-origin credential form are detected in the same browser tab session, which is a correlated attack sequence
credential_interactionWhen a login form on the page would submit credentials to a different domain than the one shown in your browser

Telemetry events carry the domain, never the full URL, together with the signal and decision fields listed above. Our servers reduce any address to its domain before storage. No credentials, page content or user identifiers are included.

Telemetry storage and retention

Scan records and telemetry events are stored on a Postgres database hosted by Render Services, Inc. in Frankfurt, Germany (EU). Scan records are deleted after 30 days and telemetry events after 90 days. No extension data is transferred outside the European Economic Area for storage.

MSP account security monitoring

For MSP administrator accounts, we record the IP address of the most recent successful API key authentication request made directly to our API (not requests from the browser extension). This is used exclusively for security monitoring, specifically for detecting whether a tenant API key has been compromised and is being used from an unexpected location. This IP address belongs to the MSP administrator making the API request, not to any browser extension end user. It is retained for the duration of the tenant relationship and deleted on key rotation or contract termination. Lawful basis: legitimate interest (GDPR Art. 6(1)(f)), because key-compromise detection is a security measure that protects both PhishWatch and the MSP customer.

6. Local storage

PhishWatch stores the following data locally in your browser using chrome.storage.local:

  • User allowlist: domains you have chosen to trust via "Continue anyway"
  • Telemetry opt-in preference: your choice of whether to enable telemetry
  • Session state: in-memory only, cleared when the tab closes

This data stays on your device and is never transmitted to our servers.

7. Third-party services

Domain age checking (RDAP/WHOIS): PhishWatch's backend queries publicly available domain registration data to detect recently registered domains. For most domains, this uses RDAP (Registration Data Access Protocol), a public ICANN-maintained service requiring no API key. For German (.de), Austrian (.at), and Swiss (.ch) domains, a direct WHOIS query is sent to the relevant national registry (DENIC, nic.at, or SWITCH). Only the domain name is sent, with no session IDs, signal data or user information. These are public infrastructure services, not commercial third parties. If the query fails or returns no data, this check is skipped and navigation proceeds normally.

Render Services, Inc.: Our backend API and database are hosted on Render's managed platform in Frankfurt, Germany (EU). Render processes data on our behalf under a data processing agreement. The database is encrypted at rest (AES-256). For enterprise and compliance details, see our compliance page or ask for our GDPR Article 32 technical measures document.

No other third-party services receive any data from the PhishWatch extension.

This website (phishwatch.io)

The website is separate from the extension and is hosted by Netlify, Inc., which processes visitor IP addresses to deliver pages. If you click "Accept" in the cookie banner, the site also loads Google Analytics (Google) for visit statistics and Leadfeeder (Dealfront) to identify which companies visit. Both set cookies and may process your IP address, and Google may transfer data to the United States. If you click "Decline" or ignore the banner, neither is loaded. You can change your choice by clearing this site's data in your browser. The legal basis is your consent (GDPR Art. 6(1)(a)). The pilot application form is processed by Netlify Forms and used only to respond to your application.

8. Chrome permissions

PhishWatch requests the following Chrome permissions:

  • scripting: runs PhishWatch's own bundled detection scripts in pages, for example to notice when a page writes a command to your clipboard. No remote code is ever loaded.
  • storage: stores your local allowlist, preferences and the signed detection rules.
  • alarms: schedules the periodic check for updated detection rules.
  • Access to all websites (http and https): needed so detection runs on whatever page you visit. Pages are analysed locally, and data leaves your browser only as described in Section 3.
  • api.phishwatch.io: sends flagged addresses and signal names to our backend for risk scoring.

PhishWatch does not request: tabs, history, webNavigation, webRequest, cookies, or any other browsing data permissions.

9. Security

PhishWatch is built on Chrome Manifest V3 with a strict permissions model. The extension uses no eval() and loads no remote code: every script ships inside the extension package, and detection rule updates are signed data, not code. All communication with our backend uses HTTPS/TLS 1.2+. All secrets are stored as environment variables and never committed to code or logs.

10. Your rights and controls

Opt out: You can disable telemetry at any time via the extension popup. Detection continues normally without telemetry.

Uninstall: Uninstalling PhishWatch via Chrome's extension manager removes all locally stored data immediately.

Data deletion: To request deletion of any stored records, contact privacy@phishwatch.io. We will action deletion requests within 30 days.

Data portability: Because session IDs are randomly generated UUIDs with no link to your identity, we cannot extract records attributable to a specific individual. We can delete all records associated with your organisation's domain on request.

Override: PhishWatch uses a fail-open design. All warnings are overridable, and you can always choose "Continue anyway."
